# 能力开关表

> 能力开关控制业务流节点是否调用具体能力。能力不能绕过业务流直接运行。

## 状态

- `core`：基础治理能力，不能关闭。
- `on`：已有运行证据，默认可用。
- `manual`：需要用户明确触发。
- `experimental`：试验中，仅在声明节点使用。
- `blocked`：缺依赖、权限、数据或运行环境。
- `retired`：已退役，保留历史与替代指针。

## 规则

- `core` 能力不能关闭。
- `manual` 能力必须由用户明确触发。
- AI 辅助能力不能直接生成或发送最终对外交付物，除非业务流登记了明确授权。
- 任何自动化上线前，必须定义读写范围、依赖、人工确认和失败回退。
- `blocked` 能力不能成为活动业务流的必需能力。
- 能力关闭时只影响挂接节点，不直接删除业务资产。
- 从 `manual` / `experimental` 升为 `on` 前，必须有对应节点的验证记录。

## 新增能力

1. 确认服务哪条业务流的哪个节点。
2. 默认设为 `manual` 或 `experimental`。
3. 定义读写范围、依赖、人工确认、失败回退和关闭影响。
4. 用真实或批准的代表性输入试跑。
5. 把证据写入交付清单声明的验证记录目录。
6. 验证通过后再决定是否改为 `on`。
